# Security Policy

## Supported versions

Security fixes are provided on a best-effort basis for the `main` branch and the
latest GitHub release. Older releases and downstream forks are not supported.

## Reporting a vulnerability

Use GitHub Private Vulnerability Reporting from this repository's **Security**
tab to report a suspected vulnerability. Include the affected component, impact,
reproduction steps, and any suggested mitigation that can be shared safely.

Do not report vulnerabilities involving sensitive information in a public issue,
pull request, discussion, commit, or log. Never post API keys, database URLs,
authorization headers, service-account material, private paper content, or any
other secret. If a credential may already have been exposed, revoke or rotate it
through its provider before sharing a redacted report.

Ordinary bugs that do not expose a security weakness or sensitive data may be
reported through public GitHub issues.
